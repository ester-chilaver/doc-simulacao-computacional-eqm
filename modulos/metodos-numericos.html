00 — Por que estamos aqui

A Ponte entre Equação e Simulação

No Módulo 1 chegamos à equação de difusão de Einstein. Mas há um problema: a maioria dos sistemas que vamos modelar — populações neurais, propagação de atividade cortical, falência metabólica — não tem solução analítica fechada. Não existe fórmula para calcular diretamente.

É aqui que entram os métodos numéricos: algoritmos que aproximam a solução passo a passo, transformando uma equação diferencial em uma sequência de cálculos que o computador pode executar.

01
Integração Temporal (EDOs)
De Euler a RK4, passando pelo meio-termo de Heun — e generalizando para sistemas de duas variáveis acopladas. Usado no Módulo 3 para simular a dinâmica Wilson-Cowan.
02
Integração Espacial (EDPs)

RK4 avança no tempo, Diferenças Finitas calcula o espaço. Isso é o Córtex Visual em isquemia.
01 — Antes de Aproximar

Enxergando uma EDO sem Resolvê-la

Antes de sair aproximando qualquer coisa, vale a pena parar num ponto que costuma passar batido: uma equação diferencial já nos entrega um mapa, mesmo sem sabermos ainda como percorrê-lo.

Pense numa EDO genérica dy/dt = f(t, y). Ela não te diz onde a partícula, a população ou a atividade neural vai estar — mas te diz, para qualquer ponto (t, y) do plano, qual é a inclinação da curva que passa por ali. É como se alguém te entregasse uma bússola: em cada esquina do mapa, ela aponta para onde a trilha segue. Ela não te dá a trilha inteira, mas se você souber ler as bússolas espalhadas pelo mapa, consegue enxergar o formato da solução antes de calcular um único número.

Vamos usar, ao longo de todo este módulo, a mesma EDO de exemplo — o decaimento exponencial, um dos poucos casos que também tem solução analítica fechada, o que nos dá uma régua de comparação confiável para testar cada método numérico que vier a seguir:

dy/dt = −k · y(t)    y(0) = y₀
k Taxa de decaimento
y(t) = y₀e^{−kt} Solução analítica exata — nossa régua de comparação
🧭
Lendo o campo de bússolas

Para essa equação, f(t, y) = −k·y não depende de t — só da altura y em que você está. Isso significa que, em cada altura, todas as bússolas apontam para a mesma inclinação, não importa em que instante. Quanto mais alto y está, mais inclinada para baixo é a seta (queda mais rápida); perto de y = 0, as setas quase deitam (quase não há mais o que decair).

Qualquer curva-solução, para qualquer y₀ escolhido, é obrigada a "seguir as setas" em todo ponto por onde passa. É exatamente essa obrigação que o Método de Euler, na próxima seção, vai transformar em um algoritmo.

02 — O Método Mais Simples

Método de Euler

Já vimos o campo de bússolas para o decaimento exponencial. O Método de Euler parte de uma ideia geométrica simples: se eu sei onde estou agora e sei qual é a minha inclinação (a derivada), posso estimar onde estarei daqui a um pequeno passo h.

yi+1 = yi + h · f(ti, yi)
h Tamanho do passo de tempo — quanto "avançamos" a cada iteração
f(t,y) A própria EDO: nos diz qual é a inclinação em cada ponto
♦️
A intuição geométrica

Imagine que você está num ponto da curva e só pode ver a tangente — a reta que toca a curva naquele instante. Euler diz: "siga essa reta por um passo h, e use o novo ponto como ponto de partida para o próximo passo."

O problema: a tangente é exata apenas naquele instante. À medida que a curva se dobra, a reta tangente se afasta da realidade. Quanto maior o h, maior o desvio acumulado — é o erro de truncamento.

03 — Um Meio-Termo

Euler Melhorado: Olhando Adiante antes de Comprometer o Passo

O Método de Euler tem um problema de miopia. Ele mede a inclinação só no ponto de partida e assume, ingenuamente, que essa mesma inclinação vale para o passo h inteiro. Se a curva se dobra pelo caminho — e ela sempre se dobra — Euler já era: seguiu reto quando devia ter virado.

Pense numa trilha de descida íngreme. Euler olha a inclinação onde está agora e desce reto por h metros, sem checar nada pelo caminho. O Euler Melhorado (também chamado de Método de Heun, ou preditor-corretor) faz uma coisa a mais, barata e poderosa: antes de comprometer o passo, ele dá uma olhada adiantada — desce hipoteticamente os h metros com a inclinação de Euler, espia qual seria a inclinação lá na frente, e só então decide o passo real usando a média das duas inclinações.

k₁ = f(ti, yi)   (preditor — inclinação no início)
ypred = yi + h·k₁
k₂ = f(ti+h, ypred)   (corretor — inclinação no ponto previsto)
yi+1 = yi + (h/2)(k₁ + k₂)
k₁ A mesma inclinação "míope" que Euler usaria sozinho
ypred Um Euler experimental — só para descobrir a inclinação lá na frente, nunca vira o resultado final
(k₁+k₂)/2 A correção: em vez de confiar cegamente em k₁, usamos a média entre início e fim previsto
♦️
Por que isso é um "meio-termo"?

Euler usa 1 avaliação de inclinação por passo e erra por um fator de h a cada passo (erro de truncamento local O(h²)). Heun gasta 2 avaliações — dobra o custo — mas em troca ganha uma ordem inteira de precisão: o erro local cai para O(h³). É o primeiro degrau de uma escada que vamos subir mais uma vez na próxima seção, com o RK4.

04 — Mais Precisão, Mesmo Espírito

Runge-Kutta de 4ª Ordem (RK4)

Heun já nos deu a receita: olhar mais de uma inclinação e tirar a média melhora a aproximação. Por que parar em duas? O RK4 leva essa mesma ideia adiante e usa quatro estimativas distribuídas ao longo do intervalo h, combinadas numa média ponderada. O resultado é uma aproximação dramaticamente melhor com o mesmo tamanho de passo.

05 — Generalizando

Quando Uma Variável Não Basta

Até aqui, todo o nosso mundo cabia em uma única variável: y(t). Uma população, uma concentração, uma atividade decaindo sozinha. Mas o córtex não decide seu destino isoladamente — ele é uma negociação constante entre populações que se empurram mutuamente. Para modelar isso, precisamos resolver mais de uma equação ao mesmo tempo, cada uma influenciando a outra a cada passo.

A boa notícia: nada do que construímos até aqui precisa ser jogado fora. Basta trocar a variável escalar y por um vetor Y = (y₁, y₂, …), e a mesma fórmula do RK4 continua valendo — só que agora cada k é, ele próprio, um vetor:

dY/dt = F(t, Y)    Y = (y₁, y₂, …, yn)
Y Vetor de estado — todas as variáveis acopladas, atualizadas juntas
F(t, Y) Um vetor de derivadas — a "inclinação" de cada componente, que pode depender de todas as outras
k₁ = F(ti, Yi)
k₂ = F(ti+h/2, Yi+h/2·k₁)
k₃ = F(ti+h/2, Yi+h/2·k₂)
k₄ = F(ti+h, Yi+h·k₃)
Yi+1 = Yi + (h/6)(k₁ + 2k₂ + 2k₃ + k₄)
Idêntico ao RK4 escalar da seção anterior — a única mudança é que Y e cada k agora carregam mais de um número.
🐇
Um exemplo clássico: presa e predador

O exemplo mais conhecido de duas variáveis que se empurram mutuamente vem da ecologia, não da neurociência — mas a estrutura matemática é a mesma que vamos reencontrar no Módulo 03. Populações de presas (x) crescem sozinhas, mas são reduzidas pelos predadores (y); predadores crescem à custa das presas, e minguam na ausência delas:

dx/dt = α·x − β·x·y    dy/dt = δ·x·y − γ·y

Repare na semelhança estrutural: uma população que se autoalimenta (α·x) sendo contida por outra (−β·x·y), enquanto essa segunda só existe por causa da primeira (δ·x·y) e decai sozinha (−γ·y). Essa é exatamente a "gramática" que o par excitação/inibição do Wilson-Cowan vai usar no Módulo 03 — só que lá as duas populações não formam ciclos de caça, formam o equilíbrio (ou o colapso) da atividade cortical.

06 — O Desafio Espacial

Diferenças Finitas e o Laplaciano

Euler, Heun e RK4 resolvem o problema temporal — sozinhos ou em sistemas acoplados, como acabamos de ver. Mas a equação de difusão tem um componente espacial — o Laplaciano ∇². Para simular a propagação de atividade no tecido cortical precisamos calcular a segunda derivada numa grade discreta.

A ideia: no computador, o espaço não é contínuo — é uma lista de pontos separados por Δx. A segunda derivada num ponto i pode ser aproximada pelos seus dois vizinhos imediatos.

∂²u/∂x² ≈ (ui+1 − 2ui + ui−1) / Δx²
ui Valor no ponto central — o que queremos analisar
ui±1 Vizinhos imediatos — quem "puxa" o ponto central
Δx Espaçamento da grade — resolução espacial da simulação
🔍
A intuição geométrica do Laplaciano discreto

A fórmula acima pode ser lida como: "quanto ui difere da média dos seus vizinhos?" — exatamente a definição intuitiva de curvatura.

Se ui for maior que seus vizinhos (pico), o resultado é negativo → a difusão vai espalhar energia para fora. Se for menor (vale), o resultado é positivo → energia flui para dentro. Se a atividade já está uniforme (rampa), o Laplaciano é zero → sem difusão.

Isso é exatamente o que a equação do calor de Fourier descrevia — agora discretizado numa grade de neurônios.

Por que condições de contorno periódicas?

No código do notebook, usamos np.roll para calcular os vizinhos — isso assume que as bordas da grade se conectam (periodicidade). Neste módulo essa escolha é didática: o modelo de borda importa menos que entender a dinâmica central.

No Módulo 4, quando simularmos o córtex visual real, usaremos condições de Neumann (fluxo zero na borda), mais realistas para tecido neural.

07 — A Síntese

Integrando Espaço e Tempo

Temos agora as duas metades do problema: RK4 para o tempo, Diferenças Finitas para o espaço. A equação de difusão combina os dois:

∂u/∂t = D · ∂²u/∂x²
RK4 Integra ∂u/∂t — avança no tempo
Dif. Finitas Calcula ∂²u/∂x² — avança no espaço
D Coeficiente de difusão — velocidade de espalhamento

Mas há uma restrição fundamental: não podemos escolher Δt e Δx livremente. Existe um limite de estabilidade — o critério de von Neumann:

Δt ≤ Δx² / (2D)
violação Se Δt for maior que esse limite, a solução explode numericamente
intuição Em um passo de tempo, a informação não pode "viajar" mais que um Δx

def metodo_euler(f, y0, t_span, h):
    """Resolve a EDO usando o Método de Euler."""
    t_start, t_end = t_span
    t = np.arange(t_start, t_end + h, h)
    y = np.zeros(len(t))
    y[0] = y0

    for i in range(len(t) - 1):
        y[i+1] = y[i] + h * f(t[i], y[i])

    return t, y
python — metodo_heun 
def metodo_heun(f, y0, t_span, h):
    """Resolve a EDO usando Euler Melhorado (Heun / preditor-corretor)."""
    t_start, t_end = t_span
    t = np.arange(t_start, t_end + h, h)
    y = np.zeros(len(t))
    y[0] = y0

    for i in range(len(t) - 1):
        k1 = f(t[i],     y[i])              # preditor
        k2 = f(t[i]+h,  y[i] + h*k1)       # corretor, no ponto previsto

        y[i+1] = y[i] + (h/2) * (k1 + k2)  # média das duas inclinações

    return t, y
python — metodo_rk4 
def metodo_rk4(f, y0, t_span, h):
    """Resolve a EDO usando Runge-Kutta de 4ª Ordem."""
    t_start, t_end = t_span
    t = np.arange(t_start, t_end + h, h)
    y = np.zeros(len(t))
    y[0] = y0

    for i in range(len(t) - 1):
        k1 = f(t[i],       y[i])
        k2 = f(t[i] + h/2, y[i] + h/2 * k1)
        k3 = f(t[i] + h/2, y[i] + h/2 * k2)
        k4 = f(t[i] + h,   y[i] + h     * k3)

        y[i+1] = y[i] + (h/6) * (k1 + 2*k2 + 2*k3 + k4)

    return t, y
python — rk4_sistema 
def rk4_sistema(F, Y0, t_span, h):
    """RK4 para sistemas de EDOs — Y0 é um vetor (array) de estado inicial.

    Idêntico ao metodo_rk4 escalar: só troca y por Y (vetor) e f por F
    (uma função que retorna um vetor de derivadas).
    """
    t_start, t_end = t_span
    t = np.arange(t_start, t_end + h, h)
    Y = np.zeros((len(t), len(Y0)))
    Y[0] = Y0

    for i in range(len(t) - 1):
        k1 = np.array(F(t[i],       Y[i]))
        k2 = np.array(F(t[i] + h/2, Y[i] + h/2 * k1))
        k3 = np.array(F(t[i] + h/2, Y[i] + h/2 * k2))
        k4 = np.array(F(t[i] + h,   Y[i] + h     * k3))

        Y[i+1] = Y[i] + (h/6) * (k1 + 2*k2 + 2*k3 + k4)

    return t, Y

# Exemplo — presa (x) e predador (y):
def F_presa_predador(t, Y, alpha=1.1, beta=0.04, gamma=0.4, delta=0.02):
    x, y = Y
    return [alpha*x - beta*x*y, delta*x*y - gamma*y]
python — laplaciano_1d 
def laplaciano_1d(u, dx=1.0):
    """Laplaciano 1D por Diferenças Finitas (contorno periódico).
    
    Nota: contorno periódico é didático — no Módulo 4 usaremos
    condições de Neumann (fluxo zero) para o tecido cortical real.
    """
    u_prev = np.roll(u, 1)   # u_{i-1}
    u_next = np.roll(u, -1)  # u_{i+1}

    return (u_next - 2 * u + u_prev) / (dx**2)
